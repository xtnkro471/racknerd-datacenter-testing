## 三步测完一个机房

**第一步，ping 看基础延迟和丢包。**


ping 204.13.154.3


Windows 按 Win+R 输 cmd，Mac 和 Linux 直接开终端。重点看两样：平均延迟（avg）和丢包率。丢包比延迟更致命，1% 以上的丢包在网页上就是偶尔卡住不动。

**第二步，traceroute 看去程路径。**


tracert 204.13.154.3        # Windows
traceroute 204.13.154.3     # Mac / Linux


中间跳数落在哪个城市、哪个运营商出口，能看出线路干不干净。去洛杉矶却先绕日本、或者中间有几跳连续超时，这条线就不算优质。

**第三步，Looking Glass 反向测，加下载测速。**

打开对应机房的 LG 页面，选 MTR，输入你本地的公网 IP，点运行。这一测是从机房往你这边推数据，测的是回程。同一页面上再下一个 100MB 或 1GB 的测试文件，看实际下载速度。

国内用户还可以用两个在线工具省事：`itdog.cn/ping/` 输入测试 IP，看全国各省三大运营商的延迟分布，比自己一台机器测有代表性；`ping.pe/` 输入 IP，绿色代表通、红色代表丢包，页面下方自动生成 MTR，能看出数据包最后几跳落在哪。Linux 上想自己跑，`mtr -r -c 10 你的IP` 生成十包报告。

下载测速前先把迅雷、Steam、视频、代理软件全关掉，不然测的是你自己带宽的上限，不是线路的上限。

## 测出来的数字怎么读

第三方测评给出的参考区间大致是这样：

| 线路 | 延迟区间 | 判断 |
| --- | --- | --- |
| 美西（洛杉矶、圣何塞、西雅图） | 130–180ms | 优秀，建站和日常操作都顺 |
| 美西 | 150–200ms | 正常水平，绝大多数人够用 |
| 美西 | 200–250ms | 能用，但后台点一下要等一下 |
| 美西 | 250ms 以上 | 换机房，别硬买 |
| 美东（纽约、芝加哥、达拉斯、阿什本） | 200ms 以上 | 属正常，国内访问本来就这样 |
| 欧洲（阿姆斯特丹、斯特拉斯堡、都柏林） | 300ms 以上 | 正常，只适合面向欧洲的业务 |

洛杉矶 DC-02 有实测口径给到移动宽带 150–180ms、联通略低、电信 150ms 上下，属于美西里的优等生。

延迟低不等于速度快。ping 只反映往返时间，真正决定网页打开体验的是带宽和回程路由。有人 ping 150ms 但下载只有 500KB/s，有人 ping 190ms 却能跑满 300M 宽带。所以第三步的下载测速不能省，300M 宽带能跑到 30MB/s 左右，说明线路和端口都正常。

## 测试 IP 测的是去程，回程要看 Looking Glass 的 MTR

这是多数汇总文章一句话带过、但实际最关键的一点。

`ping 204.13.154.3` 测的是数据从你家宽带出去、到达机房这一段，也就是去程。而你访问网站时，页面内容是从机房推回你手机和电脑的，走的是回程。两个方向的路由经常不一样：去程走电信 CN2 直连洛杉矶，回程可能绕一圈欧洲再回国，ping 值看着还行，实际下载和视频加载就是慢。

所以顺序应该是：先 ping 拿到延迟基线，再 tracert 看自己去程绕不绕，然后用 Looking Glass 的 MTR 输入本地 IP 看回程。MTR 报告的最后几跳如果落在中国大陆的出口，说明回程直连；如果最后几跳还在日本、新加坡、欧洲打转，这条线回程就是绕的。绕路的机房，ping 再好看也别选。

**电信、联通、移动分别怎么选**：电信方向走 CN2 到洛杉矶通常最稳；联通走 AS4837 到圣何塞有时比洛杉矶更好；移动在西海岸几个机房差别不大，西雅图可以一试。这些是经验性判断，你自己的线路只有你自己测了才算。
